## Problem Solving Template
1)  understand the problem.<br />
2)  Ask example of Input/Output and re-confirm it. Don't make assumption on expected Input/Output.<br />
3)  Find the 3 Types test data to solve the problem - +Positive , -Negative , edge case re-confirm with interviewer.<br />
4)  Don't show excitement to solve the problem in front of interviewer. They may change the problem.<br />
5)  Never leave big pauses/silence , if problem unable to crack without westing time request politely for next problem.<br />
6)  If unable to Solve problem - impress/maximize your opportunity for next round let interviewer know "making a note of this                         problem/approach & will go back work on the same problem".<br />
7)  Ask for Hints !! if at all required.<br />
8)  Think for alternate solution.<br />
9)  If we know more than one solution - explain approaches which solution is better (Time/Space complexity wise)/ why? ask        interviewer which to apply.<br />
10)  If we are sure about optimal solution at least start with wrost case(Then show optimal if known) solution - brute force approach!!.<br />
11) Initially to improve the logic build start with Psudo code.<br />
12) Keep Talking while implementing the code - explain the thinking approach.<br />
13) After solving the problem please execute step 3.<br />
14) Debug your failure to with breakPoints , watch variables fix and re-run your code.<br />
15) Try to ask good & relevant questions - opportunity to exhibit the skill.<br />
16) Do not ask stated / bad questions, create trust & transparency during interview. <br />
